# 无线音乐自建单通用融合设计方案

## 一、目的与范围

将运营商渠道人工登记的无线音乐工单纳入统一工单工作台、建单与处理页、查询及基础数据管理框架，通过表单和处理规则承接业务差异。

本期包括正式登记、保存处理、任务提醒、组内调剂、结案、结案后修订、附件收集、外呼录音及明细查询导出。质检退回重提、质检看板和班组看板后续建设。新系统仅承接新建工单；旧数据不迁移，旧单继续在旧系统处理和查询。

本文已确认业务规则按讨论结论执行；页面组织、创建阶段及按钮表达为针对本轮反馈的交互设计方案，不作为新增业务决定。标注“设计建议”的细节用于原型评审，标注“待资料”的内容需补齐。

## 二、工单定位与入口

| 维度 | 定义 |
| --- | --- |
| 业务类型 | 无线音乐 |
| 平台工单类型 | 咨询 |
| 建单方式 | 人工创建 |
| 表单 | 无线音乐运营商登记，名称为设计建议 |
| 处理流程 | 建单人自处理，节点内支持组内调剂，不自动分派 |
| 统计归属 | 按表单独立统计，不计入通用咨询工单量 |

“投诉类型”保留为运营商业务字段，不据此触发平台投诉定性和投诉流程。400 进线仍使用其对应的受理流程；本方案不替代其咨询、投诉及外投规则确认。

**入口设计建议：**

1. 工单工作台增加“无线音乐自建单”保存视图，固定筛选本表单，继续使用“我的、本组、已办”等既有任务范围及状态筛选。
2. 用户点击工作台“新建工单”，打开“新建工单”工作区页签，显示“工单工作台 > 新建工单”路径。
3. 在统一新建入口选择“无线音乐运营商登记”业务表单，随后进入同一业务表单填写字段；从上述保存视图新建时预选表单，无需重复选择。咨询类型随表单只读展示，不要求用户再次选择工单类型，不增加确认页。
4. 用户填写业务号码，点击“创建并处理”，生成正式工单并进入“处理中”；后续仍在同一张表单补齐信息。该路径依次呈现工作台、表单选择、新建登记及正式处理阶段，创建成功后直接进入处理中，不增加创建确认页。
5. 查询中心支持按本表单筛选及导出，同一工单从工作台、查询中心进入同一处理页。
6. 表单可见范围绑定无线音乐处理组；产品及字典维护纳入现有后台配置管理。

## 三、建单与处理页面

建单和后续处理使用同一张业务表单，明确区分“尚未创建”和“已登记处理”两个阶段。创建成功后保留已填内容，显示真实单据与归属信息，处理人继续补齐业务信息和处理结果。

### 3.1 页面框架

按最新布局决定取消三张静态速览卡，页头下方改为左右两个可编辑业务区：左侧沿用原“问题与诉求”位置，承载来源与时限；右侧完整迁入“产品与业务号码”板块。下方集中展示问题、处理结果、退费及附件。右侧不设置客户档案卡、客户关联入口或处理归属卡，仅保留联络号码、外呼及收集材料区域。预约提醒时间收进页头，底部保留提醒操作入口。

| 页面区域 | 新建阶段 | 已保存处理阶段 |
| --- | --- | --- |
| 页头 | 显示“新建工单”、只读咨询类型及业务表单；不展示尚不存在的单号、建单时间、建单人和处理人 | 显示真实状态、标题、单号、建单人、建单时间及当前处理人；并入预约提醒时间或“未设置”状态 |
| 顶部左侧“问题与诉求” | 在原区块位置填写反馈平台、具体来源、渠道明细、接入时间、工单时效及上游流水号，按结案前必填标注 | 保留同一可编辑业务区，按当前处理人权限继续补充 |
| 顶部右侧“产品与业务号码” | 完整展示业务线、产品分类、产品名称、业务号码、运营商、省份、业务订购时间；业务号码突出标注“创建必填”，其余按阶段标注 | 保留同一板块及字段，支持产品反向带入、编辑和修订 |
| 下方主表单 | 填写问题分类、诉求、处理结果、退费及附件；允许稍后补齐 | 保留相同字段结构，支持继续填写、保存及结案校验 |
| 联络区域 | 填写联系号码；与正式工单绑定的外呼、材料收集等操作创建后可用 | 提供本单联系电话外呼、短信收集材料入口；不展示客户档案、客户关联入口或处理归属卡 |
| 数据页签 | 只呈现待填写表单，不展示虚构的处理履历、联系、通知或附件历史 | 创建成功后再展示处理履历、联系记录、通知记录和附件历史；无记录时显示真实空态 |
| 底部 | “创建并处理”“创建并结案”“取消／返回工作台”；预约提醒在正式登记后可操作 | “保存”“预约提醒”“调剂”“结案”；已结案时保留“保存修订”，其余动作按权限和状态显示 |

**创建动作：**“创建并处理”仅校验业务号码，成功后进入正式处理中；“创建并结案”校验全部结案必填项，通过后创建同一张工单并结案，校验失败仍停留新建表单；“取消／返回工作台”退出尚未创建的表单，不产生正式单据。创建及结案均一次提交，不增加二次确认页或重复选择类型。

回复时间保留在主表单，新建时尚未生成的回复时间留空并说明自动记录；调剂记录进入处理履历，处理人和建单信息集中在已登记页头，无独立归属卡。**设计建议：**顶部两块与下方内容使用同一份表单数据和统一详情滚动区域；创建成功保留当前页签和填写位置；标题可由产品名称与业务号码组合。已结案保留历史页签及修订入口，附件仍按同组上传权限处理。

### 3.2 表单分区与字段

业务号码为唯一创建必填，置于顶部右侧“产品与业务号码”板块并突出标注；其余“必填”均指结案前必填，界面按阶段标注。产品与号码整块迁移，不在下方另设重复字段。业务订购时间等选填项保持选填，后续保存不要求一次补齐全部结案信息。

| 分区 | 字段及规则 |
| --- | --- |
| 顶部左侧：问题与诉求（来源与时限） | 工单流水号选填，人工记录上游单号；反馈平台必填，支持搜索；选择微信反馈或 QQ 反馈时展示“具体来源”，引用对应群清单；渠道明细必填、自由填写，区别于具体来源；工单时效必填，仅半小时、1 小时、2 小时、24 小时；接入时间必填，默认打开新建页的当前时间，可人工修改 |
| 顶部右侧：产品与业务号码 | 业务线、产品分类、产品名称结案前必填；业务线为“5G新通话业务部、数字娱乐业务部”；产品分类及名称支持搜索，选择产品名称反向带出所属分类及业务线。业务号码创建必填，用于记录订购业务的号码，并带出运营商、省份；运营商及省份结案前必填，业务订购时间选填。以上字段完整保留在同一板块 |
| 右侧联络区域 | 联系电话用于实际联络，提供外呼、材料收集及联系记录入口；业务号码与退费号码按各自用途展示，不替代联系电话 |
| 诉求信息 | 问题分类一、二必填，按需求表对应清单维护，不随产品变化；描述内容必填；服务请求类别选填 |
| 处理结果 | 投诉类型、是否闭环、处理结果必填，保留业务选项；处理结果为长文本；回复时间由系统按保存、结案动作记录，无需人工填写 |
| 退费与凭证 | 退费号码、退费金额选填；支持上传、查看及下载附件，展示上传人和时间；处理结果出现“附件”二字时，忽略空格匹配，在保存或结案时提醒上传，不强制拦截 |

删除开通渠道、业务号码年龄、超时工单备注、本步意见。业务号码、联系电话、退费号码分别保留用途，不相互替代。

**待资料：**具体来源的必填要求、联系电话的必填要求、现有反馈平台及投诉类型等完整选项、号码归属识别失败时的处理方式。

## 四、登记、生命周期与权限

### 4.1 正式登记与个人草稿

首次操作使用“创建并处理”或“创建并结案”，明确产生正式单据；后续操作继续使用“保存”，用于更新已有工单。仅填写号码尚未提交时仍是新建阶段，正式创建后才产生工单编号、创建时间与处理人归属。

**设计建议：**平台个人草稿属于未正式登记的个人输入，不生成正式编号、不参与调剂、提醒及专项工单计数。本表单的“创建并处理”是正式登记，业务所称“暂存处理”则对应登记后的保存更新，与个人草稿区分。

### 4.2 生命周期

常规路径：工作台 → 新建工单 → 选定业务表单（已预选时直接填写） → 填写业务号码 → 创建并处理 → 处理中 → 保存补充信息 → 结案 → 已结案。

一次完成路径：填写全部结案必填信息 → 创建并结案 → 已结案。两条路径均生成正式记录，并保留创建与结案时间。

处理中可反复保存及组内调剂。调剂立即生效，接收人无需确认；转交后由新处理人继续处理，未触发的预约提醒保留原时间并改为通知新处理人。已结案工单不允许调剂。

结案后允许处理人修订业务内容，状态保持已结案，不重新打开、不新增一次结案量；保留原结案时间，记录操作人、修改时间及修改前后内容。**设计建议：**修订不刷新原业务回复时间，最后修改时间单独记录。

### 4.3 人员动作矩阵

已结案时，“当前处理人”指结案时的处理人。表单可见及查看范围仍受平台权限约束。

| 动作 | 当前处理人 | 同组其他成员 | 组外人员 |
| --- | --- | --- | --- |
| 查看工单及记录 | 可 | 可 | 按平台查询权限，只读 |
| 修改业务内容 | 可，结案后按修订执行 | 不可 | 不可 |
| 结案 | 未结案时可 | 不可 | 不可 |
| 调剂 | 已登记且未结案时可 | 已登记且未结案时可 | 不可 |
| 上传附件 | 可，含结案后 | 可，含结案后 | 不可 |
| 删除附件 | 仅本人上传的附件 | 仅本人上传的附件 | 不可 |
| 设置、修改提醒 | 未结案时可，设计建议 | 不可，设计建议 | 不可 |

调剂接收人仅限当前处理组成员。**设计建议：**调剂记录保留前后处理人、操作人和时间；原因是否填写、批量调剂是否提供不作为本期已确认要求。

## 五、客户、联系与提醒

### 5.1 业务号码与联络

本流程只记录业务号码，不自动新建客户，不展示或要求客户档案关联，不展示姓名、地址等档案字段。此调整仅作用于本业务表单，平台原有客户管理能力保持其既有范围。

业务号码是业务检索条件，不直接视为客户身份。**设计建议：**提供“按此业务号码查看相关工单、联系记录”的入口，清楚标注号码关联口径。本页不显示客户全景或客户档案卡；顶部为可编辑的左右业务区，不恢复静态速览三卡。

外呼从本单联系电话入口发起，联系记录和录音与工单关联。客户通过短信链接上传图片、音频等材料；短信和上传页面统一使用一个客服名称，由业务提供，不显示科大讯飞。

### 5.2 通用任务提醒

提醒作为可绑定正式工单的通用能力建设，区别于现有预约回访。预约提醒选填，手动选择明确时间，不按工单时效自动计算。页头显示当前预约提醒时间与状态，底部“预约提醒”入口设置或修改时间；不另设顶部提醒卡或主表单提醒分区。到时弹窗，点击打开对应工单；调剂保留原时间并转移接收人，结案后取消尚未触发的提醒。

**设计建议：**时间选择支持日期及时分秒；提醒在工作区内统一展示，用户切换工单、列表后仍可收到。离线后的补提醒、多条提醒合并及弹窗消失方式另行明确，不直接承诺浏览器关闭后仍可提醒。

## 六、配置、查询与统计

无线音乐产品目录独立于 400 工单目录，在现有基础数据管理框架维护，通过本表单引用。管理员可新增、启用及停用下拉选项。反馈平台及来源、问题分类等使用相应业务字典。

**设计建议：**停用选项不再供新选择，历史工单保留原值；字段分组、显示条件、登记与结案必填、动作权限、结案修订和统计范围按表单管理。

工作台提供任务办理，查询中心提供条件检索和明细导出。**设计建议筛选项：**工单号、上游流水号、业务号码、联系电话、状态、处理人、创建时间、接入时间、反馈平台、具体来源、产品及问题分类。列表优先展示状态、号码、产品、来源、时效、提醒时间、处理人和创建时间，支持列设置。

统计以表单独立归集，明确排除通用咨询工单量。同一工单在工作台可见，不代表计入通用咨询业务量；该排除规则不扩展为统一查询不可见或排除平台全部工单总量，其他指标按各自口径适配。专项明细导出包括业务字段、处理组、处理人及关键时间；质检数据和班组看板不纳入本期。

**设计建议：**登记量按创建时间计数，结案量按首次结案时间及结案处理人计数，保存、调剂、修订均不增加工单量。系统内近三个月明细导出、更长历史经观星台导出的范围沿会议方向评估，字段口径保持一致。

## 七、平台复用与待补齐能力

复用统一工作区、工作台保存视图、查询、建单与处理页框架，以及附件、外呼录音、通知和履历入口。重点补齐按表单驱动的字段校验、权限、单节点自处理、修订记录及专项统计排除规则，并建设通用任务提醒。

现有原型已有“创建并处理”入口及多业务展示结构；后台类型、表单设计器的保存和发布主要为演示交互，不能据此认为运行页已完整按配置执行。上述配置与运行能力需验证、补齐，不承诺零开发。

**待资料：**独立产品目录完整归属关系、原有业务字典、统一客服名称与可用短信模板、客户上传页适配方案、旧系统需平移的维护和查询功能明细。
