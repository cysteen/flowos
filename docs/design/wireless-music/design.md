# 自建单工作台产品方案

## 一、定位

同一平台内新增“自建单工作台”，承接无线音乐运营商自建单的新建、列表、处理、查询和导出。它与原工单工作台并列，共享登录、租户、人员、导航及基础组件，使用独立业务路由和记录，不耦合原工单的列表、派单、SLA、查询或统计。

本期独立范围是“无线音乐运营商登记”表单。原有 400 流程中恰好产品为无线音乐的普通工单保持原业务归属。咨询作为本业务分类保留，运营商投诉类型为业务字段；登记和结案独立归集，不计入通用咨询工单量。

## 二、信息架构

| 层级 | 设计 |
| --- | --- |
| 平台菜单 | 工单工作台之后新增自建单工作台 |
| 列表 | 贴顶我的待办／全部记录页签，全部／处理中／已结案快捷项；工具栏、折叠筛选、列设置、表格和分页与既有工作台风格一致 |
| 新建 | 从本工作台直接新建，无需在统一建单选择表单；仅业务号码创建必填 |
| 处理 | 本模块详情页，保存、组内调剂、提醒、附件及结案；终态通过修订保存 |
| 查询导出 | 本工作台内完成，不混入原查询中心，列表计数及导出使用同一数据范围 |
| 后台配置 | 沿用平台字典及产品管理入口，本表单范围独立维护，与400目录区分 |

检索按自建单字段组织：业务号码、工单编号、运营商、处理组、处理人、来源、渠道明细分别查询，模糊内容匹配描述和处理结果；创建、接入及回复时间支持到秒的区间。产品、省份、问题分类等作为可选筛选。查询、列表、状态计数和导出共用同一权限及记录范围。

路由为 `/self-service`、`/self-service/new`、`/self-service/:ticketNo`。旧业务链接兼容至新模块，保留原型已经保存的编号、附件、履历和提醒。旧业务系统历史数据仍不迁移。

## 三、交互与规则

常规办理从自建单工作台新建，填写号码后创建并处理，后续保存补充、设置提醒或组内调剂，补齐结案信息后结案。一次办结可填写完整信息后创建并结案，不增加确认页。

新建和处理共用业务编辑器：顶部左来源与时限、右完整产品与业务号码，下方诉求处理、退费和附件，右侧联络入口；页头展示实际单据和当前处理人及提醒时间。无旧三卡、客户档案、客户关联或处理归属卡。

只有当前处理人可修改和结案，同组人员均可上传附件和对已保存未结案单进行调剂；接收人限当前组，转交即时生效，无需确认。未触发提醒保持时间并转交新处理人，结案取消待提醒。已结案由处理人修订，保留原结案及回复时间，记录前后值，不重复计数。附件仅上传本人可删除。

业务订购时间选填；接入时间默认打开新建页的当前时间，可修改。业务号码、联系号码和退费号码分别使用，不自动建客户。产品按已配置映射带出分类及业务线，缺映射可手选；停用项不供新选，历史值继续展示和办理。

## 四、通用性与交付边界

业务分区、字段校验、字典产品、版本检查、附件和提醒继续使用已有通用登记能力，工作台独立承担业务入口及数据边界。本期不建设完整表单发布引擎、质检或班组看板。外呼、材料邀请及录音入口先验证交互，真实服务按技术稿对接。

完整要求见 `PRD.md`，实现边界见 `technical-design.md`，走查路径见 `acceptance.md`。

## 五、竞品参考

- [Zendesk 多工单表单](https://support.zendesk.com/hc/en-us/articles/4408846520858-Creating-multiple-ticket-forms)：以不同表单组织业务字段，支持复用字段配置思想。
- [Freshdesk 字段配置](https://support.freshdesk.com/support/solutions/articles/50000010094-understand-and-customize-ticket-fields)：提交必填与关闭必填分开配置，为分阶段补齐提供参考。
- [Zoho Desk 布局规则](https://help.zoho.com/portal/en/kb/desk/customization/layouts-and-fields/articles/understanding-layout-layout-rules-in-zoho-desk)：支持按业务布局及条件组织字段。
- [Udesk 工单接口](https://www.udesk.cn/doc/apiv2/tickets/)：人工录入、模板和受理人可分别表达，适合作为登记模型的参考。

竞品资料支持通用能力的设计依据；本平台按已确认的独立工作台、数据边界、权限和终态修订规则实施。
