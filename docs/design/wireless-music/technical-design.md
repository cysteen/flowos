# 无线音乐运营商登记技术设计

## 一、目标与实施边界

在现有 Vue 工单工作区内，以通用业务登记模型和表单模板承接人工自处理场景，复用工作台、查询、统一建单和既有工单处理路由。业务规则以同目录 `PRD.md` 为准：咨询类型、独立表单统计、不计入通用咨询工单量、不自动建客户、无客户关联入口。

本文分为原型实施与生产对接建议。原型以浏览器本地记录验证交互及数据一致性；生产接口、跨设备存储和真实外部服务另行接入。

### 2.2 原型数据模型

`src/views/tickets/types/businessRegistration.ts` 定义通用契约，`src/stores/businessRegistration.ts` 提供 `useBusinessRegistrationStore`。统一 `Ticket` 增加可选 `formTemplateId`，既有工单未设置该字段时沿原流程办理。

| 对象 | 关键内容 |
| --- | --- |
| `RegistrationTemplate` | `id/name/businessType/ticketType/groupId/groupName`，统计开关 `includeInGeneralConsultationCount`，以及 `fields/products/problemOptions/sourceOptions` |
| 字段定义 | `key/label/createRequired/closeRequired/options`；创建与结案使用同一字段集合，按阶段校验 |
| 产品定义 | `name/category/businessLine?`；业务线映射可缺省，不推测所属部门 |
| `RegistrationValues` | 号码、来源、产品、时限、诉求、处理、退费及回复时间；号码按字符串存储 |
| `RegistrationRecord` | 工单号、模板、值、状态、人员和关键时间，以及履历、附件、联系、通知和可选提醒；`revision` 用于本地过期写入检查 |
| 提醒 | `id/at/note/recipient/triggeredAt?`，与正式工单绑定 |

本模板标识为 `wireless-operator`，类型为咨询，统计开关为 `false`。已按需求表导入 45 项产品、微信／QQ 来源及问题分类；原材料未给出完整产品到业务线的映射。当前按已配置数据带出分类，缺业务线映射时手动选择；完整映射由业务补齐。

当前布局在 `registrationEditorConfig.ts` 集中生成，字段要求和字典读取模板，顶部左来源时限、右完整产品与业务号码。字段契约尚无后台可发布的区域／顺序属性；生产可扩展布局配置，不能将现有设计器展示视为完整运行时发布能力。

### 2.3 数据写入与统一查询一致性

存储按租户隔离，缓存键为 `flowos-business-registrations-v1:<tenantId>`。正式写入统一经 `commit`：读取持久化版本并校对 `revision`，本地保存成功后通过 `syncAll/syncRecord` 更新 `TICKETS` 投影；失败返回错误，不先报告成功。编辑器保存携带 `expectedRevision`，过期业务内容需重新载入核对。

`hydrate` 恢复当前租户记录，清理后重建本表单投影，避免刷新重复插入。创建、保存、调剂、结案、提醒及附件动作必须使用同一写入边界，页面不另维护一份可写详情。模板变化或租户切换后应重新匹配记录与数据范围。

投影将号码放入 `businessPhone/contactPhone/upstreamTicketNo`，不写入客户手机号或档案标识，避免号码检索被当作客户身份。`storage` 事件同步其他页面的本地变化，不能替代生产多端事务。

### 2.4 目录配置联动

字典入口为 `/flowos/admin/dicts?template=wireless-operator`，产品入口为 `/flowos/admin/products?template=wireless-operator`。`formCatalogs` 按租户、模板缓存，使用现有字典／产品管理权限及配置版本检查；`registrationTemplateOf` 解析有效目录供表单消费。

字典支持新增、启停及父子关系；产品支持新增、启停、编辑分类及补充业务线，既有名称／键值稳定，无删除。新选择校验启用项，历史停用值保留；原样保存或修订需将旧值传入阶段校验。布局仍由前端分区配置生成，不等同于后台自由布局发布。

## 三、动作、权限及审计

| 存储动作 | 约束 |
| --- | --- |
| `create` | 模板所属组成员可创建；创建并处理校验创建必填，创建并结案执行完整校验；生成一张正式记录，建单人即处理人 |
| `save` | 当前处理人更新；处理中保存允许结案字段暂缺；结案执行完整校验，修订保持终态及原结案、回复时间 |
| `transfer` | 同组成员仅可调剂处理中记录，目标必须属于本组，立即改处理人；未触发提醒同步变更接收人 |
| `setReminder/cancelReminder` | 仅当前处理人对未结案单操作；设置合法的未来时间；不按运营商时效自动计算 |
| `markReminderTriggered` | 校验本人、所属组、状态、到期时间及未触发条件，写入触发标记和通知，避免重复触发 |
| 附件与联络动作 | 同组可上传，删除校验上传本人；外呼及材料邀请由当前处理人对未结案单操作 |

权限同时控制操作显示和存储函数，不能只依赖按钮置灰。原型使用演示姓名及分组判断，组外查看使用现有查询入口权限；生产需替换为稳定用户、组标识及平台实际数据权限。

履历记录创建、保存、调剂、提醒、结案、修订及附件操作；业务字段变化保留前后值、操作人和时间。创建并结案一次写入，避免先生成可分派任务再关闭。结案清除待触发提醒；修订不创建新单，不重复结案计数。

状态只允许创建进入处理中／已结案、处理中结案、已结案修订保持原状态。正式编号、建单人、创建及结案时间不接受业务字段覆盖；处理组和处理人只通过规定动作变更。生产服务从登录上下文判断操作人，不信任客户端提交的姓名或权限标志。

## 四、交互集成约束

编辑器以有无 `ticketNo` 区分新建与正式处理，已结案需显式进入修订模式。新建成功后进入原工单详情路由并关闭新建页签，普通保存更新当前记录。布局、按钮及阶段标注遵循 PRD，渲染不产生客户档案或额外归属卡。

既有预约回访与任务提醒保留不同语义。工作区组件每秒检查到期任务，同时响应记录修订及登录人变化；只触发当前用户的有效待办，先持久化 `triggeredAt` 和通知再展示，防止切页重复弹出。调剂后重新读取接收人，结案后移除待提醒。该检测不具备浏览器关闭后或跨设备送达保证。

## 五、统计与文件演示边界

`isGeneralConsultationTicket` 结合类型及模板统计开关判断通用咨询口径，已用于查询列表口径提示及 CSV 字段；其他真实咨询量报表需采用同一规则。不能把本模板从统一查询或全部工单集合删除；专项报表按模板归集，其他指标按各自定义适配。

两入口共用 `useRegistrationQueryCatalog`，查询目录合并配置和历史记录，含停用产品／来源。`registrationFeedback/registrationSource` 分别过滤反馈平台和具体来源；`registrationTimeField` 默认 `createdAt`，可选 `accessTime`，共用日期区间。普通工单仍按更新时间，不被登记表单覆盖。状态快捷项使用全部／处理中／已结案，行操作按登记权限判定。

登记及首次结案时间用于专项计数，保存、调剂、修订不重复计数。原型 CSV 按当前筛选导出全部匹配记录，包含模板字段、人员、状态及关键时间；生产大批量导出应使用统一查询条件生成导出任务，并与观星台对齐口径。

原型附件经 `FileReader` 转 Data URL 缓存，受本地容量限制；新建先创建单据再关联文件，文件失败保留正式单并提示补传。原型未接号码归属服务，运营商／省份当前手选。`recordContact`、`recordMaterialInvite` 仅记示意；录音只有 `recordingUrl` 展示位。生产文件改用文件服务引用，真实外呼、短信、材料上传及号码查询分别对接。

## 六、生产对接建议

下表是生产职责及交付资料清单，不是已存在的接口合同，不作为用户再次审批事项。

### 6.1 外部职责

| 对接职责 | 需落实的能力与资料 |
| --- | --- |
| 工单服务 | 按模板创建、保存、结案、修订及组内调剂；允许不关联客户；服务端统一校验状态、权限、字段及审计 |
| 模板与字典 | 独立目录、完整产品业务线映射、旧反馈平台／投诉类型／闭环选项；停用项保留历史值；补齐字段布局配置 |
| 号码归属 | 可用查询服务及识别失败处理；业务号码、联系号码、退费号码分开使用 |
| 客户材料 | 业务提供统一客服名称及可用短信签名／模板；上传页不显示科大讯飞；明确链接有效期、支持类型、文件回传及权限 |
| 外呼录音 | 本单外呼关联标识、呼叫结果与录音回传、播放和下载权限；不以号码匹配代替工单关联 |
| 消息任务 | 服务端调度、接收人变更、结案取消、重复投递控制及离线补发；采用平台消息服务实现跨设备送达 |
| 查询与报表 | 明确租户／组数据范围、专项导出字段、通用咨询量排除规则及观星台口径，不迁旧数据 |

### 6.2 建议操作契约

对接时优先映射平台已有服务，下列为请求／结果约定，不预设已实现的 URL。

| 操作 | 请求关键项 | 结果及约束 |
| --- | --- | --- |
| 获取模板／目录 | 表单标识、配置版本 | 字段阶段要求、布局、有效选项及产品归属；历史值可展示 |
| 创建处理／结案 | 表单标识、业务值、办理动作、幂等请求号 | 正式编号、状态、系统时间、版本及字段错误；不要求客户档案标识 |
| 保存／结案／修订 | 工单号、预期版本、业务值、动作 | 服务端校验当前处理人和阶段，返回新版本；修订保留原终态及时间 |
| 调剂 | 工单号、预期版本、组内目标人员标识、选填说明 | 归属、提醒接收人及履历一起更新，拒绝跨组或已结案单 |
| 设置／取消提醒 | 工单号、预期版本、提醒时间及事项 | 接收人从当前处理人派生，返回任务标识和状态 |
| 附件／查询导出 | 工单号、文件服务标识；或数据范围及查询条件 | 校验上传归属、查看／删除权限；返回一致的记录集或导出任务 |

成功结果统一包含工单标识、版本、更新时间及变更后的状态；失败区分字段校验、权限不足、版本冲突和外部服务异常，避免前端自行猜测是否已提交。

### 6.3 事务、并发及外部回传

创建以租户、操作人及幂等请求号去重，重复提交返回同一工单；保存、调剂和结案采用预期版本检查。若另一组员已调剂，旧处理人保存返回冲突或权限错误，刷新后重新办理。原型已有本地版本检查，但没有服务端事务及幂等保证。

业务值、归属、审计及提醒变更在同一事务提交；首次结案时间只写一次。消息与统计事件使用持久化待发送记录，按事件标识去重。提醒投递前再核对当前处理人和工单状态，调剂更新接收人，结案取消未触发任务；客户端按提醒标识去重展示。

材料服务返回文件标识及本单关联信息，回调按事件标识幂等；文件查看和删除在服务端鉴权，类型、大小及链接有效期由服务配置。外呼传递本单标识，录音回传按呼叫标识关联，不以号码相同代替本单关联。服务端生成系统时间和编号，接入时间保留人工维护语义，金额采用明确精度，展示时区与平台统一。

## 七、验证与验收衔接

源码回归入口为 `verification/source-check.cjs`，从仓库根执行 `node docs/design/wireless-music/verification/source-check.cjs`。回归覆盖数据模型、权限、配置及历史值等规则；浏览器已验证配置新增停用联动、历史值保存、跨页提醒、调剂、修订、附件权限，以及两页签过期保存拒绝并保留输入。查询需检查来源、独立产品、创建／接入日期及状态条件叠加。

业务验收用例和真实 Vue 截图见 `PRD.md`。生产另验服务端并发与幂等、真实文件／短信／录音、消息回传及完整查询报表；本地回归结果不替代外部服务验收。
