# 无线音乐自建单工作台技术设计

需求正文已迁入[无线音乐自建单PRD](<../../../../../PRD/【1120】无线音乐自建单 产品需求文档(PRD).md>)。业务规则以已通过业务评审的3011交互稿及同步后的PRD为准，本文说明实现职责与生产接入契约。

## 一、模块边界

自建单工作台作为同平台独立业务模块运行，菜单权限为 `self-service`，路由为 `/self-service`、`/self-service/new`、`/self-service/:ticketNo`。列表、新建、处理、查询及导出均由本模块负责，不依赖原工单工作台的列表状态、统一建单或查询中心。

共享平台登录、租户、用户与组织、工作区外壳、页签、基础 UI 及按表单区分的后台目录配置。业务记录由登记存储单独持久化，不投影写入 `TICKETS`，原工单查询、统计、派单和 SLA 不消费自建单记录。原有 400 流程中产品为无线音乐的普通工单属于原工单域，不按产品名称迁移。

本文区分原型实现及生产对接契约。浏览器本地记录及演示外呼不代表生产服务已接通，材料收集当前没有可达页面入口。

## 二、实现职责

| 模块 | 职责 |
| --- | --- |
| `src/config/navigation.ts`、`roles.ts` 与路由配置 | 独立菜单、查看权限、列表／新建／处理路由及旧业务链接兼容 |
| `src/views/self-service/SelfServiceWorkbenchView.vue`、`SelfServiceCreateView.vue`、`SelfServiceOperationView.vue` | 列表范围和筛选、独立新建、处理页容器及本模块页签 |
| `src/components/workspace/WorkspaceTaskTabs.vue`、既有 `TicketFilterBar.vue`、`TicketToolbar.vue` | 共用纯页签、快捷项和工具栏；通过本模块参数提供筛选及列定义，不读取原工单数据 |
| `src/views/self-service/useSelfServiceLeaveGuard.ts` | 页面切换及关闭时保留未保存输入，按用户选择放弃或继续填写 |
| `src/views/self-service/registrationListQuery.ts` | 自建单各业务字段、模糊文本及创建／派单／回复／更新时间匹配，不使用原工单数据源 |
| `src/views/self-service/useRegistrationQueryCatalog.ts`、`legacyRegistrationProjection.ts` | 独立查询目录及停用历史值；单独清理旧版已标记登记投影的兼容适配 |
| `src/stores/businessRegistration.ts` | 正式记录、状态权限、并发版本、履历、附件、联系、通知及提醒，使用独立缓存 |
| `src/views/tickets/types/businessRegistration.ts` | 登记模板、字段、数据模型和分阶段校验；物理目录不代表业务依赖原工单集合 |
| `src/views/tickets/components/business/BusinessRegistrationEditor.vue` 及同目录字段组件 | 共用本业务的新建、处理中及修订编辑器；返回、成功及号码检索跳本模块 |
| `src/components/tickets/GlobalTicketReminders.vue` | 平台工作区常驻到期提醒，打开 `/self-service/:ticketNo` |
| `src/stores/formCatalogs.ts`、既有字典／产品管理页 | 按租户与表单范围维护独立选项和产品，保留停用历史值 |

不再由原工作台、统一建单或原查询组件导入登记存储并计算自建单数据。原处理页处理普通工单；旧登记链接的有限重定向仅作兼容，不恢复共享办理流程。

## 三、模型及持久化

`RegistrationTemplate` 包含模板标识、业务类型、咨询分类、处理组、字段要求、产品、问题和来源目录。当前模板为 `wireless-operator`，保留 `includeInGeneralConsultationCount: false` 业务口径，独立域不向通用咨询统计提供普通工单记录。

| 对象 | 关键内容 |
| --- | --- |
| 字段定义 | `key/label/createRequired/closeRequired/options`，创建与结案按阶段校验 |
| 产品 | `name/category/businessLine?`，缺业务线映射时允许手选，不推测归属 |
| `RegistrationValues` | 业务／联系／退费号码、来源、产品、时限、诉求、处理、退费及回复时间，号码按字符串存储 |
| `RegistrationRecord` | 工单号、模板、值、状态、处理组、建单人、处理人、创建／修改／结案时间、版本及各类记录 |
| 附件及联系 | 文件标识、元信息、上传人时间；本单联系号码、操作人、结果和可选录音引用 |
| 提醒 | `reminders[]`：`id/at/note/recipient/triggeredAt?/acknowledgedAt?`，一单可多条；旧版单字段 `reminder` 读入迁数组；已触发且无消费时间为待知晓，绑定本单及当前处理人 |

业务缓存继续使用 `flowos-business-registrations-v1:<tenantId>`，目录配置按租户、模板保存。新登记使用独立号段 `IFLYZJ-YYYYMMDD-00001`，此前原型已有的 `IFLYZX` 编号、附件、履历及提醒保持不变，不重新编号或重复创建。旧业务系统数据仍不迁移。

`commit` 读取最新持久化集合并核对版本后写入，成功后更新登记存储及其修订信号；登记存储不导入或更新 `TICKETS`。`hydrate` 仅恢复当前租户登记记录；独立兼容适配在启动时清理此前明确带登记标识的内存投影，不按产品名称或号码删除普通工单。切租户时重载本模块数据，存储事件同步同租户其他页面变化。

编辑器加载记录时捕获 `expectedRevision`；保存、结案和修订明确提交基线版本。其他页面修改业务内容或归属时，有未保存输入则保留并提示载入最新，无未保存输入可更新显示。仅附件或提醒元数据变化时，在业务值和归属未变的条件下推进版本，不清空输入。该机制用于原型防覆盖，不等同于跨设备事务。

## 四、权限、状态及审计

独立菜单控制模块查看入口，办理仍依据当前租户、实际处理组和处理人。组外具备自建单查看权限的账号只读。生产校验使用稳定用户及组标识，不能信任客户端姓名或按钮状态。

| 动作 | 校验及提交结果 |
| --- | --- |
| `create` | 所属组成员可创建；草稿可空白并占编号，正式创建须号码；已选有子项的平台还要求具体来源，直接结案执行完整校验；由建单人负责 |
| `save` | 当前处理人、有效版本；处理中允许结案字段暂缺，结案补齐；已结案按修订保存并保留原系统结案时间，业务回复时间可修改且留痕 |
| `transfer/transferCrossGroup` | 仅处理中当前处理人发起；普通人员仅组内，指定角色还可选择允许目标组及成员；即时更新归属、未触发预约接收人及待处理退回通知接收人 |
| `addReminder/updateReminder/cancelReminder` | 当前处理人、处理中；工单可挂多条提醒，追加或按id修改／取消；时间须为明确未来时刻；已触发不可修改或取消，包括已打开编辑弹窗的竞态；不按时效推算 |
| `markReminderTriggered` | 按提醒 id 触发；处理人、接收人、状态、到期及未触发条件均符合，先写触发标记和通知再展示；已触发项保留为历史 |
| `acknowledgeReminder` | 当前处理人、接收人为本人、仍处理中且已触发；幂等写acknowledgedAt。知晓／关闭／去处理均成功持久化后才移除或跳转；失败核对最新有效性，仍有效则保留卡片 |
| 附件 | 同组上传、本人删除，已结案仍可补充；异步读取完成后重新核对租户、工单和操作人上下文 |
| 外呼／材料邀请 | 只有处理中当前处理人的外呼入口可达，挂断写本单联系记录；草稿及闭单不可呼出。材料、短信及邮件函数暂无页面调用，不能视为已交付入口 |

生命周期包括草稿、处理中和已结案。草稿可空白保存，与正式单共用编号序列，转正式保留编号及记录创建时间，但只有首次正式创建事件计入登记量。保存和调剂不新增状态，创建并结案一次写入。结案清理提醒列表，触发事件仍保留于履历；修订保持终态及原系统结案时间。回复时间是可人工维护的业务字段，普通保存不自动生成，结案为空时补当前时间，闭单修订也可修改并审计前后值。

班组长「退回重开」后内部状态仍归「处理中」；列表与处理页标题徽章对外展示「已退回」（对齐平台工单子状态配色），并写入 `reopenedAt` 直至原处理人再次结案。同一工单多次退回时，仅最新一条 `待处理` 的 `reopen` 通知参与待办；更早的同款通知在写入新通知时标记为「已被新退回替代」。处理人点击右下角 GlobalTicketReminders「已知晓」或「去处理」仅将对应 `reopen` 通知置为已知晓，**不**取消「已退回」展示；再次结案后清除 `reopenedAt` 并恢复「处理中／已结案」展示。

退回与预约提醒双通道：进入自建单工作台时，对已知晓去重的待处理退回可弹出一次 Ant Design Vue `Message` 轻提示（文案指向右下角「工单退回重开」）；持久操作与多条工单堆叠在 `GlobalTicketReminders`，与预约到期卡片**同时**展示（退回在上、预约在下，面板 `max-height` 可滚动）。`Message` 与全局卡片共用 `localStorage` 键（用户 + 通知 id），刷新不重复 Toast；通知已知晓或不再待处理时清理对应键。预约提醒仍仅走全局卡片，不与退回互斥。

## 五、列表、查询及导出

列表直接从有权查看的登记记录取数，默认“全部”，另提供“我的”；“我的”包含本人处理中及本人创建或负责的草稿，不含已结案。列表条数包含草稿，与正式登记量不同。页面复用既有工作台的视觉和控件模式，包括贴顶范围页签、状态快捷项、工具栏、折叠筛选区、可选筛选、列设置和分页；复用UI不引入原工单取数、动作及统计。

`RegistrationListQuery` 分别管理业务号码、工单编号、运营商、处理组、处理人、来源、渠道明细和模糊文本等条件。产品、省份、问题分类等通过可选筛选配置展示。来源使用反馈平台和具体来源的父子关系，来源和产品可查询停用及历史值，不能以400目录替代。

时间字段为创建、派单（accessTime）、回复及更新时间，接受秒级本地日期时间，按所选字段比较；显式时间边界不扩展为整日。纯匹配函数供列表、计数、分页和导出共用。默认按更新时间倒序，可按派单、更新及承诺剩余时效表头排序；时效按派单时间加承诺计算，缺派单时间回退记录创建时间，不接原SLA引擎。收起筛选保留查询，移除可选字段清空条件，筛选后页码保持有效。列显隐与顺序按租户、用户保存，不改变业务查询范围。

明细导出勾选时取所选，未勾选时取当前筛选全集，包括完整业务字段、状态、处理组、人员、关键时间及最近未触发预约时间，不按列显隐裁剪，并按记录创建时间限定近三个月。生产大批量导出使用独立查询条件生成任务。正式登记取首次创建工单事件（草稿暂存不计），首次结案取首次结案事件及当时处理人；保存、调剂、再次结案及修订不重复计数，不能用当前closedAt代替首次结案事件。

## 六、目录、文件及消息边界

字典入口 `/admin/dicts?template=wireless-operator`、产品入口 `/admin/products?template=wireless-operator` 继续使用平台现有后台权限；按表单区分本业务与 400 数据。支持新增、启停、父子关系及产品归属维护，已有键值和名称稳定，无删除。前端和存储校验均传入原记录值，允许历史停用值原样保存、结案及修订。

当前字段分区及顺序由 `registrationEditorConfig.ts` 集中生成，不代表后台具备自由布局发布能力。需求清单导入45项产品，完整产品到业务线映射仍需补齐。当前号码归属由演示样例及模拟回退带出运营商、省份并允许调整，不是真实归属识别服务。

原型附件经 `FileReader` 转 Data URL 后缓存，受本地容量限制；生产使用文件服务标识及鉴权链接。新建先生成正式单，再关联文件，上传失败保留正式单并提示补传。外呼、短信邀请、客户上传和录音回传分别对接真实服务，不用号码相同替代本单关联。

提醒在工作区常驻组件中检查，跨模块页面仍可触发，详情目标始终为自建单路由。面板每轮从已触发、未消费、本人负责及本人接收的有效记录恢复，刷新或重新进入后恢复未消费卡片；已知晓项不重弹。旧数据缺消费时间按未消费兼容，可能补展示一次。工作区未运行时无法主动展示，再次运行可补触发仍有效的过期预约；后台节流及休眠可能延迟。本地断网不等同浏览器关闭，跨设备需服务端调度及消息服务。

## 七、生产操作契约

优先复用平台基础服务，业务操作采用自建单域接口，不把记录写入原工单池后再过滤。

| 操作 | 请求关键项 | 服务端约束 |
| --- | --- | --- |
| 获取模板／目录 | 模板及配置版本 | 返回阶段要求、有效选项、产品归属及可展示历史值 |
| 创建处理／结案 | 业务值、办理动作、幂等请求号 | 无需客户档案标识；返回单号、状态、版本、系统时间及字段错误 |
| 保存／结案／修订 | 单号、预期版本、业务值及动作 | 校验当前处理人、状态及阶段，修订保留终态关键时间 |
| 调剂 | 单号、预期版本、目标组／人员、选填说明 | 当前处理人及跨组角色校验；归属、预约接收人、未处理退回通知接收人和审计同一事务更新 |
| 设置／取消提醒 | 单号、预期版本、提醒时间及事项 | 接收人由当前处理人派生，投递前复核有效状态 |
| 附件／查询导出 | 文件引用或独立查询条件 | 验证租户与数据范围、上传／删除权限，返回记录或导出任务 |

生产创建以租户、操作人和请求号幂等去重，保存、调剂及结案使用版本冲突检查。业务值、归属、审计、提醒及首次结案计数在同一事务提交；持久化消息事件按标识去重。文件和录音回调按事件或呼叫标识幂等关联。失败明确区分字段错误、权限不足、版本冲突和外部服务异常。

## 八、验证边界

自动验证应覆盖业务规则、版本冲突、租户隔离、异步附件、目录历史值、独立查询及 `TICKETS` 不被登记动作写入。浏览器走查新增菜单、列表／新建／处理闭环、调剂提醒、结案修订、旧记录恢复和原工单域隔离，具体顺序见 `acceptance.md`。

生产补充稳定权限、服务端并发与幂等、文件容量、真实短信及客户上传、录音回传和跨设备消息验收。原型验证结果与命令见 `review.md`，不能用演示记录替代生产服务结果。
